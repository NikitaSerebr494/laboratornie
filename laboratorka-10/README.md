## 1. Надёжный ввод размера

`read_positive_integer()` крутится в цикле, пока не получит целое число больше нуля, и
различает два случая:

- `int()` не смог разобрать строку → «Это не целое число, попробуйте снова.»
- число разобралось, но `<= 0` → «Число должно быть больше нуля.»

Проверка последовательности `abc`, `0`, `-2`, `3` выдаёт два сообщения и возвращает `3`;
это закреплено в `test_read_positive_integer_skips_bad_input`.

## 2. Чтение таблицы

Формат `matrix.txt`:

```
2 3
1 -2 3
4 0 -6
```

`read_matrix(path)` читает файл в UTF-8, разбирает заголовок (два положительных целых),
затем ровно `rows` строк по `cols` целых чисел. Проверки:

- пустой файл → `ValueError` «файл пуст»;
- заголовок не из двух чисел или с нечисловыми значениями → ошибка строки 1;
- нулевые или отрицательные размеры → ошибка строки 1;
- пустая строка внутри данных → ошибка с номером этой строки;
- не то количество чисел в строке → ошибка с номером строки;
- нечисловая ячейка → ошибка с номером строки;
- лишние строки после данных → ошибка с номером первой лишней строки;
- нехватка строк данных → ошибка «недостаточно строк данных»;
- один обычный перевод строки в конце файла допустим, отсутствие перевода тоже.

Отсутствующий путь даёт `FileNotFoundError` из самой функции — основная программа
переводит его в понятное сообщение.

## 3. Отчёт и вариант 2

Условие варианта 2 — сумма отрицательных элементов исходной матрицы. Для `matrix.txt`
это `-2 + (-6) = -8`, что совпадает с таблицей вариантов. Если отрицательных элементов
нет (в том числе для пустой матрицы), `selected_sum` возвращает `0`. Функция не зависит
от формы матрицы, поэтому подходит и для 1×1, и для 1×N.

`report.txt`:

```
Суммы строк: 2 -2
Суммы столбцов: 5 -2 -3
Результат варианта: -8
```

Суммы берутся из `table.row_sums` и `table.column_sums`, вариант считается по исходной
матрице, а не по преобразованной.

Запись безопасная: текст сначала пишется в `report.txt.tmp` и только потом заменяет
`report.txt` через `os.replace`. Если чтение, разбор или проверка данных упали, запись
не начинается вовсе.

## Сохранность старого отчёта — ручная проверка

Перед проверкой сохранён SHA-256 файла `report.txt`, затем выполнены три неудачных
запуска: битый заголовок, отсутствующий путь и файл в windows-1251. Каждый раз код
возврата `1`, в stderr выведено сообщение, хэш отчёта остался прежним
(`2D19F379…8F1B`), временный `.tmp` не появился. Итог: при некорректном входе
существующий отчёт не изменяется.

## Что проверяет `test_files.py`

Проверки из задания (временная папка `tempfile.TemporaryDirectory()`):

- `1 1\n7\n` → `[[7]]`;
- пустой файл → `ValueError`;
- заголовок `0 3` → `ValueError`;
- заголовок `1 2` и строка `1` → `ValueError` с указанием строки 2;
- заголовок `1 2` и строка `1 x` → `ValueError` с указанием строки 2;
- заголовок `1 1` и две строки данных → `ValueError`;
- отсутствующий путь → `FileNotFoundError`.

Дополнительно: матрица из `matrix.txt`, допустимый перевод строки в конце, пустая строка
внутри данных, заголовок без двух чисел, поведение `read_positive_integer`, точный текст
отчёта и `selected_sum` без отрицательных элементов. Ожидаемые исключения ловятся через
`try/except ValueError` и `try/except FileNotFoundError`; в ветке `else` стоит
`assert False, "Ошибка не обнаружена"`.
